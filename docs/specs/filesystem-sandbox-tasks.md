# 文件系统沙箱兜底任务拆分

## 文件范围

| 文件 | 变更 |
| --- | --- |
| `monkeycode/tools/workspace.py` | 明确并补强真实路径解析、项目内包含关系判断及可写路径解析入口。 |
| `monkeycode/tools/files.py` | 读取、写入、编辑统一使用正确的守卫入口，避免创建文件时遗漏父目录检查。 |
| `monkeycode/tools/search.py` | 枚举文件时只接受守卫确认后的真实项目内文件。 |
| `monkeycode/permissions.py` | 权限硬检查使用与文件工具一致的可读/可写解析语义。 |
| `tests/test_workspace.py` | 新增路径守卫单元测试。 |
| `tests/test_permissions.py` | 补充允许模式与允许规则不能绕过边界的测试。 |
| `tests/test_tools.py` 或现有文件工具测试文件 | 补充读、写、编辑、搜索的端到端符号链接逃逸测试。 |
| `tests/test_agent_tool.py` | 补充 worktree 子 Agent 不能经父项目或项目外链接逃逸的回归测试。 |
| `README.md` | 澄清文件工具边界及不等同完整 OS 级沙箱的限制。 |

## 有序任务

### 1. 固化路径守卫语义

1. 检查现有路径守卫的根目录解析、候选路径解析和包含关系判断。
2. 增加或明确用于已有路径与可写路径的两个入口，保证可写目标的存在父目录在解析符号链接后仍位于项目内。
3. 所有失败统一抛出既有工作区边界错误类型，不暴露项目外文件内容。
4. 验证：新增单元测试覆盖项目内相对路径、项目内绝对路径、`..` 逃逸、项目外绝对路径、项目外文件符号链接、项目外目录符号链接及项目内合法符号链接。

依赖：无。

### 2. 接入所有内置文件 I/O 工具

1. 读取和编辑使用“已有路径”解析语义。
2. 写入使用“可写路径”解析语义，并在创建父目录和写入前使用受信任目标。
3. 确认错误结果保持 `path_outside_workspace`，不改变普通文件、目录和不存在文件的既有错误语义。
4. 验证：工具级测试确认读、编辑、覆盖、创建在逃逸路径上均失败，项目外目标内容不变；项目内普通文件和合法绝对路径成功。

依赖：任务 1。

### 3. 接入搜索与权限硬检查

1. 文件发现和代码搜索枚举每个候选文件前通过路径守卫，跳过解析后位于工作区外的文件。
2. 权限管理对读、编辑调用已有路径检查，对写入调用可写路径检查；确认其在规则匹配、允许模式与交互确认之前执行。
3. 验证：搜索不返回项目外符号链接内容；允许模式、会话允许规则和模拟用户允许均不能放行路径逃逸。

依赖：任务 1。

### 4. 验证 worktree 边界与兼容性

1. 用临时 Git 仓库创建 worktree 子 Agent 场景，确认其项目内操作正常。
2. 验证从 worktree 经父项目路径、项目外绝对路径或符号链接访问均失败。
3. 验证非 Git 主工作区与既有权限、普通 Agent 流程保持兼容。
4. 验证：相关 Agent/worktree 回归测试通过。

依赖：任务 2、任务 3。

### 5. 文档、全量验证与提交准备

1. 更新 README，说明文件工具使用真实路径边界，且此功能不隔离 Shell、网络或子进程。
2. 运行与本功能相关的测试，再运行完整 `pytest -q`、`python -m compileall -q monkeycode tests`、`python -m monkeycode --help` 和 `git diff --check`。
3. 记录实际通过/失败结果；若失败，先定位并修复至通过后再交付。

依赖：任务 4。

## 建议提交点

1. `harden workspace file path resolution`：完成任务 1 至 3 与对应测试。
2. `document filesystem sandbox boundary`：完成任务 4 至 5、README 和全量验证。
