# 文件系统沙箱兜底规格

## 背景

MonkeyCode 的文件工具和子 Agent 可以读取、写入、编辑及遍历工作区文件。需要把“只能访问项目目录”的约束作为不可被普通权限规则绕过的安全边界，并阻止通过相对路径、绝对路径或符号链接访问项目目录外的文件。

本规格中的“沙箱”指文件系统访问边界，不宣称提供容器、低权限令牌或网络/进程隔离等完整 OS 级沙箱。

## 目标

所有由 MonkeyCode 内置文件工具发起的文件读取、写入、编辑和项目内搜索，只能作用于当前项目目录或其解析后的真实子路径。

## 功能需求

1. 系统收到文件路径后，必须先将项目根目录和目标路径解析为真实路径，再判断目标是否位于项目根目录内。
2. 对读取、编辑和搜索，任何经解析后指向项目目录外的符号链接、硬编码绝对路径或 `..` 路径都必须被拒绝，且不得返回目标内容。
3. 对创建或覆盖文件，系统必须验证目标文件的现有路径以及父目录的真实路径均位于项目目录内；符号链接链路指向项目目录外时必须拒绝写入。
4. 被拒绝时，工具返回统一的结构化“路径在工作区外”失败结果；权限允许模式、会话允许规则和用户确认均不得放行该访问。
5. 项目根目录自身以及其真实子目录内的普通文件操作必须保持可用，现有相对路径和合法绝对路径调用兼容。
6. 子 Agent 使用 Git worktree 时，应以该子 Agent 的 worktree 作为独立项目根目录应用相同约束。

## 非功能需求

1. 路径判定在 Windows、Linux 和 macOS 上使用一致的安全语义。
2. 拒绝结果不得泄露项目目录外文件的内容。
3. 现有权限提示、危险命令拦截及 worktree 流程保持兼容。
4. 新增或调整的行为必须有自动化测试覆盖正常路径、路径逃逸和符号链接逃逸。

## 边界与不做的事

1. 本次不把 `run_command` 置入 OS 级容器、AppContainer、Restricted Token、seccomp 或 cgroup；Shell 仍是独立的安全边界问题。
2. 本次不限制网络访问、进程创建、环境变量、注册表或项目目录内代码运行后的副作用。
3. 本次不承诺防御攻击者在检查与实际打开文件之间并发替换路径的内核级竞态；这需要平台专用的受限句柄或 OS 沙箱后端。
4. 本次不改变用户主动配置的工作区根目录，也不允许多个项目根目录。

## 验收标准

1. 读取或编辑 `../secret.txt`、项目外绝对路径以及指向项目外文件的符号链接，均返回结构化拒绝结果，且项目外文件未被读取或修改。
2. 向指向项目外目录的符号链接路径创建/覆盖文件被拒绝，项目外目标不存在或内容不变。
3. 项目内普通文件、项目内符号链接和合法绝对路径均可按现有行为读写编辑。
4. 文件搜索不会返回经符号链接位于项目外的文件内容或路径。
5. 即使权限配置为允许、会话规则允许或交互确认允许，项目外文件访问仍被拒绝。
6. 子 Agent worktree 内的合法文件操作成功；其路径不能借助父项目或项目外符号链接逃逸。
7. 相关自动化测试、完整测试套件、编译检查和差异空白检查通过。
